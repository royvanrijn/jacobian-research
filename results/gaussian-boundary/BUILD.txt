Build and verify the current Gaussian boundary manuscript

Run from this directory in Linux/WSL. Dependencies: Python 3 with sympy
and pymupdf, and a TeX installation providing latexmk and pdflatex.
The repository virtual environment already provides the Python packages.
The exact Python, package and TeX versions used for the retained PDF are
recorded in verification.json under build_environment.

Check artifact identities and selected exact algebraic identities:
    ../../.venv/bin/python verify.py

Also compile from scratch and compare every rendered page with the PDF:
    ../../.venv/bin/python verify.py --build
This check leaves the retained PDF and verification record unchanged.
Auxiliary TeX files are created in a temporary directory.

After reviewing intentional source edits, rebuild the PDF and refresh its
source/PDF/checker identities:
    ../../.venv/bin/python verify.py --build --refresh

For a plain TeX build, run:
    latexmk -pdf -interaction=nonstopmode -halt-on-error manuscript.tex

All 22 TeX files in verification.json are required. No research-note input
is needed. The verifier follows the actual input graph and checks labels,
citations, the metadata abstract, and selected counterexample, shear and
frame identities. The algebra replay also uses check_formal_identities.py;
its hash is recorded alongside verify.py. The checker does not certify the general formal-frame arguments,
analytic estimates or full ternary-cubic classification. Existing finite
control receipts are preserved. Independent mathematical review and
publication remain separate from these internal checks.
