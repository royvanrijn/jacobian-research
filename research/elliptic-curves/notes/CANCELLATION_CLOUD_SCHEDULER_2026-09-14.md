# From first recovery to certified cloud yield

The [first adaptive programme](CANCELLATION_ADAPTIVE_SCHEDULER_2026-09-14.md)
established faster next-direction recovery on retained banks, but its fresh
pilot returned five independent cloud directions to V3's six. This successor
tests the specific failure mechanism: stopping after one point and fitting
only one witness per successful cloud can underprice additional directions.
The original results and source locks remain unchanged.

**The two-direction policy fails its frozen promotion gate.** Across 24 new
rank20 controls it returns 39 independently certified directions in 460.734
CPU seconds, versus factor-free V3's 40 in 429.056 seconds. Both reach the
two-direction target on 16 inputs. No fresh two-direction trial follows this
failure. The [completed summary](../../artifacts/generated-results/elliptic-curves/cancellation_cloud_scheduler_v1/summary.json)
and [receipt audit](../../artifacts/generated-results/elliptic-curves/cancellation_cloud_scheduler_v1/retained-audit.json)
retain the failed gate and all partial gains.

## Mathematical and statistical contract

The exact adjugate height law and q-only residue probabilities are reused.
For each anchor and real/local state, let `F_j` be the empirical fraction of
independent development witnesses affordable in box `j`. After completed
boxes, `C` is the statewise maximum of those fractions. The marginal exposure
is

\[
 m_j=\sum_s w_s\max(F_{j,s}-C_s,0).
\]

This is a scheduling surrogate, not a rational-point density theorem. In
particular, it omits unknown tails beyond the development search box and
does not make anchor directions independent.

The new fit uses all independently admitted directions in the **545 retained
V2 factor-free development calls**, instead of only their first witnesses.
Every positive cloud receives a standalone portable rank certificate and an
independent Sage finite-group certificate. Each retained radius is reconstructed
exactly in both implementations of the coordinate calculation. There are
**41 independent directions in 39 positive clouds**, only two more witnesses
than the first-direction fit. All 545 calls remain in their original order
and scope. Full-cloud training costs 79.211296 CPU seconds; its separate
reconstruction and fit check costs 3.978223 seconds.

The smoothed rate in each existing anchor bucket is
`lambda=(certified directions+1)/(completed calls+10)`. Each anchor starts
with a Gamma surrogate of shape `4*lambda` and rate `4`. A completed cloud
adding `g` independent columns updates shape by `g` and rate by its new
exposure. Timeout observations update neither. All returned points are
considered; repeated points or finite columns in the known span add no reward.

The estimated count in a new box is `mu=(shape/rate)*m_j`. With `k` directions
left in the fixed target, the scheduler prices

\[
 \mathbb E\min(\operatorname{Poisson}(\mu),k)
 =k-e^{-\mu}\sum_{n=0}^{k-1}(k-n)\frac{\mu^n}{n!}.
\]

For `k=1` this is `1-exp(-mu)`; for `k=2` it is
`2-(2+mu)*exp(-mu)`. The policy compares this expected credit per estimated
CPU across all prepared boxes and opening another anchor. Its cost model
still adapts from completed backend calls. All actual CPU, including failed
preparation, full-cloud classification and independent certification, is charged.

The **search subgroup remains fixed during this two-direction exposure**.
It is the certified starting subgroup and its compatible retained bank, not
an invented new height lattice after every admitted point. The output group
contains every new admitted cloud direction. Using that output as a later
search basis requires a newly verified compatible landscape and new budget.

## Frozen independent control

The [protocol design](../../artifacts/generated-results/elliptic-curves/cancellation_cloud_scheduler_v1/design.json)
selects four previously untested j groups from each of six retained families.
Within a group, the highest eligible starting rank and lexical bank choose
the input. Within a family, rank20 is preferred and a fixed hash breaks ties.
Eligibility requires a separately certifiable endpoint at least two ranks
larger. The resulting roster has **24 rank20 starting subgroups**.

All preceding CPU groups are excluded, and the q-only mixture is refitted
after removing these 24 groups too. The mixture uses 1,818 training j groups
and has weight `0.9433487052635122`. Known endpoints are available only to
control construction, preflight and analysis; the worker sees the starting
equation, subgroup, bank and frozen fit. This is a new CPU holdout within a
corpus already used for research development, not an externally pristine test.

Both arms have the same fixed objective of **two added directions**, 40 search
CPU seconds, H125000 ceiling and 48 anchors. The adaptive arm may use all
432 model/height jobs. V3 uses its retained order and one H125000 factor-free
box per anchor. Each complete returned cloud is admitted before testing the
stopping condition, so output can exceed the two-direction target.

Promotion requires all of the following under the frozen rule:

- at least as many completed two-direction targets as V3;
- at least as many **uncapped** total added independent directions;
- at least 10% more uncapped directions per complete CPU;
- a central 97.5% paired family/stratum bootstrap interval wholly above parity,
  using 10,000 draws and seed 20260914.

Every arm independently verifies its maps, squares, selected actions, complete
cloud admission and enlarged rank before publishing success. Timeouts remain
explicit. Fit and shared preflight CPU are also reported separately and charged
to the adaptive candidate alone in the conservative campaign comparison.
Common retained-bank construction is outside this input interface.

Only a passing control gate permits a separately frozen generic-only fresh
two-direction trial with cold construction charged. Failure does not trigger
a larger allowance or repeat on these cases. Rank32 remains **UNKNOWN**.

## Completed outcome and exact boundary

| Arm | Two-direction targets | Uncapped directions | Complete CPU seconds | Point calls |
|---|---:|---:|---:|---:|
| Factor-free V3 | 16/24 | 40 | 429.056284 | 565 |
| Adaptive cloud | 16/24 | 39 | 460.733865 | 2,306 |

The adaptive/V3 direction-rate ratio is **0.907964**, with central 97.5%
paired interval **[0.800495, 1.062687]**. The 128.774538 seconds of fit,
training and shared preflight cost are separate; charging them entirely to
the candidate reduces its campaign ratio to **0.709625**. No elapsed-time
proxy replaces CPU in these figures.

Both arms recover the same 16 two-direction targets. Each also retains seven
one-direction partial successes and one zero-direction result. V3 has one
three-direction cloud, counted in full. The adaptive arm has 16 two-direction
clouds. Across both arms all **79 added directions** have independent Sage
finite-group rank certificates. There are 2,870 completed point calls and
one explicit timeout, with no unresolved preparation. The eight V3 misses
exhaust their 48-anchor banks; seven adaptive misses exhaust estimated
exposure and one reaches the CPU cap. None proves a rank upper bound.

This rejects the specified Gamma/Poisson cloud policy under its finite
protocol. It neither reverses the earlier first-recovery comparison nor
proves that cancellation has no useful predictive value. Cloud-count fitting
adds only two development directions, and the same fixed anchor can keep
producing points already admitted to the output subgroup.

The [exact subgroup witness](../../artifacts/generated-results/elliptic-curves/cancellation_cloud_scheduler_v1/subgroup-boundary.json)
independently certifies a development chain of ranks **18,19,20**. Its first
new point `P` has primitive old-chart height 124499. For the same curve and
anchor `Q`, extending the anchor word by zero leaves `Q`, the pointed forms
`N,D,q`, the coordinate of `P` and every p-adic cancellation valuation
unchanged. Before adjoining `P`, the rank19 certificate proves that it is
independent of the rank18 subgroup. Afterwards it is a displayed generator,
while the other cloud point still adds a certified direction. Thus features
depending only on `E,Q,P` and their cancellation cannot determine independence
correctly for **every** possible known subgroup. This is an information
boundary for subgroup-blind classification, not a negative theorem about
average prediction or a subgroup-aware scheduler.

The empirical radial CDF has a second explicit limitation: its witnesses
are truncated at old height 125000. Once a base box completes at that height,
the surrogate can assign zero marginal mass to neighbours reaching previously
unsearched old coordinates outside the fitted range. This is a model-support
boundary, never an exact exclusion. A later exploration policy must state
how it treats that unmeasured tail.

## Enlarged-basis integration gate

A separately frozen [integration check](../../artifacts/generated-results/elliptic-curves/cancellation_basis_refresh_v1/protocol.json)
uses the highest certified adaptive cloud in the four-fibre pilot, with the
case hash breaking ties: family `x948-11952-a1-01191`, `t=-11/18`, certified
rank18. This is labelled development data. It makes **zero point-search
calls** and does not bypass the failed fresh-transfer gate above.

The [implementation](../cas/cancellation_basis_refresh.py) reuses the retained
16-row generic bank00, extends each class through all four new parity states,
and builds a landscape for the actual reconciled rank18 basis. It verifies
the subgroup independently, compares integer CVP against the original
rational solver, and checks every selected anchor by independent Sage group
arithmetic. Both 64-coset landscapes agree byte-for-byte; all 77 selected
centres pass, with the first 48 exported in a
[compatible bank](../../artifacts/generated-results/elliptic-curves/cancellation_basis_refresh_v1/prepared-bank.json).
The CVP theorem is for the recorded rounded positive numerical height
metric, not an exactly certified canonical-height matrix or the full generic
shell bank.

The complete isolated check costs **5.175586 CPU seconds**, including
1.242915 seconds of production and 1.953847 seconds of rational reference
replay. It passes its predeclared 10-second gate, one quarter of the existing
40-second search allowance, under hard limits of 60 CPU and 90 wall seconds.
This establishes one affordable implementation path for changing the search
basis; it gives no multi-curve cost or later-gain advantage.

The subsequent [basis-aware control](BASIS_AWARE_AMPLIFICATION_2026-09-14.md)
tests actual enlarged subgroups on new whole-j controls, with complete-cloud
certification, compatible bank replay, reset epoch state and all costs charged.
Its separately recorded failure does not change this integration result.
The original fixed-bank cloud failure remains retained.

## Implementation and replay

[`cancellation_cloud_policy.py`](../cas/cancellation_cloud_policy.py) implements
the expected-yield scheduler. The new
[worker](../cas/cancellation_cloud_cpu.py),
[independent verifier](../cas/verify_cancellation_cloud.py) and
[training/replay module](../cas/cancellation_cloud_training.py) are separate
from all frozen predecessor sources. Four focused regressions cover the
Poisson credit, positive-cloud update, timeout semantics and overlap accounting.

The [entry point](../cas/cancellation_cloud_programme.py) separates input
freezing, fits, proofs, execution, reporting and packaging:

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  sage -python research/elliptic-curves/cas/cancellation_cloud_programme.py run
sage -python research/elliptic-curves/cas/cancellation_cloud_programme.py report
sage -python research/elliptic-curves/cas/cancellation_cloud_programme.py replay
sage -python research/elliptic-curves/cas/cancellation_cloud_programme.py pack
sage -python research/elliptic-curves/cas/verify_cancellation_cloud_programme.py
sage -python research/elliptic-curves/cas/cancellation_basis_refresh.py check
```

`run` resumes only unstarted arms of its exact sealed cohort. An interrupted
or unreceipted arm is retained and stops execution. `replay` reconstructs
arithmetic without point searches. Packaging retains all raw calls, source
locks, training witnesses, fits and independent verification receipts.
The cloud bundle contains **4,650 files / 10,300,380 bytes**; the separate
basis-refresh bundle contains **240 files / 395,828 bytes**. Both pass complete
member-hash verification. The cloud protocol hash is
`8d7dbc720f4de2683b5e9b695bccd5289b726adcb694542a351f213af3ed8e8e`.
The accounting audit and subgroup-boundary checker were added after execution
and are explicitly bound as supplementary checkers; the pre-execution source
closure and protocol were not retagged. Default audits check retained receipts;
the original arithmetic verification is inside the timed workers.
