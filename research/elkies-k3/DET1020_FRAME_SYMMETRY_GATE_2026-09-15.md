# The retained determinant1020 frame does not support the order-four mechanism

**A fixed-frame computational gate.** The new
[arithmetic MW17 existence witness](DET1020_ARITHMETIC_MW17_EXISTENCE_2026-09-15.md)
has integral height-lattice isometry group exactly {I,-I}. Consequently this
particular fibration has no nonidentity pointed symplectic involution, and
cannot be the parent for the retained
[order-four correlated-gain construction](ORDER_FOUR_LIFT_CORRELATED_GAIN_MECHANISM_2026-09-15.md).
This says nothing about other rootless frames on that surface or about
correlated gains without this symmetry.

The source admits the rationally marked NS and proves existence of the
fibration. Its explicit equation and17 section coordinates remain uncomputed.
The present calculation needs only its certified integral frame Gram; it
neither compiles an equation nor searches for another frame.

The [checker](scripts/verify_det1020_frame_symmetry_gate.py) runs PARI2.15.4
`qfauto` on that literal rank17 Gram. The returned group has order2 and the
single generator -I. A replay recomputes the complete automorphism group and
compares source hash, checker hash and result. The
[certificate](../artifacts/generated-results/elkies-k3-det1020-frame-symmetry-gate-v1/result.json)
retains these values. Completeness relies on PARI's exact automorphism algorithm;
no independent implementation, formal verification or external review is claimed.

For the geometric interpretation, a pointed automorphism fixes the unimodular
U generated by the fibre and zero section. A nonidentity symplectic involution
on a Picard19 K3 has an eight-dimensional anti-invariant subspace in NS.
Its action on the rank17 frame would therefore have trace9-8=1, as derived
in the [involution criterion](X1092_ROOTLESS_INVOLUTION_GLUE_GATE_2026-09-15.md).
Neither I nor -I has that trace. There is no need to test discriminant gluing
after this failure. A pointed nonsymplectic base involution would compose
with fibre inversion to give the excluded symplectic involution, so it does
not bypass this gate.

The fixed calculation allows20 CPU seconds,25 wall seconds and1GiB, with one
PARI worker and a128MiB stack. It finishes in about0.05 seconds. Initial harness
attempts exposed two execution issues: changing PARI's stack on a line abandons
that line's remaining expressions, and the default worker count exceeded the
memory cap. Separate setup lines and one worker resolve both; the Gram and
mathematical scope were unchanged. The checker requires an explicit success
marker and does not treat PARI's process exit code alone as success.
